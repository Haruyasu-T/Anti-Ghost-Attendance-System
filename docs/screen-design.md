# 画面設計

[要件定義](requirements.md)と[API設計](api-design.md)に対応する画面のラフ．担当Cが `app/templates/` に実装する．

前提として，学生の画面はスマホの縦画面．教員のQR表示は教室のプロジェクター投影で，後ろの席からでも読める大きさにする．教員の管理画面はPCのブラウザ．

## 画面の流れ

```
                    ┌──────────────┐
                    │  ログイン    │
                    └──────┬───────┘
                           │ role で分岐
            ┌──────────────┴──────────────┐
            ▼                             ▼
     【教員】授業一覧              【学生】ホーム
            │                             │
            ├─ セッション開始 ──┐         ├─ QRを読み取る ──┐
            │                   ▼         │                  ▼
            │            QR表示画面       │           読み取り結果
            │            （投影用）       │
            │                   │         └─ 出席履歴
            └─ 出席状況一覧 ◀───┘
                    │
                    └─ 手動修正
```

QRを読んだ場合は，カメラアプリから直接 `/scan` に来る（未ログインならログイン画面を経由する）．

## S1. ログイン（共通）

```
┌────────────────────────────┐
│                            │
│      出席管理システム      │
│                            │
│  学籍番号 / 職員番号       │
│  ┌──────────────────────┐  │
│  │                      │  │
│  └──────────────────────┘  │
│                            │
│  パスワード                │
│  ┌──────────────────────┐  │
│  │                      │  │
│  └──────────────────────┘  │
│                            │
│  ┌──────────────────────┐  │
│  │       ログイン       │  │
│  └──────────────────────┘  │
│                            │
│  ⚠ IDまたはパスワードが   │
│    正しくありません        │
│                            │
└────────────────────────────┘
```

エラーは「IDが存在しない」と「パスワードが違う」を区別しない．アカウントの存在を推測させないため．レート制限にかかったときだけ「しばらく待ってから再度お試しください」と出す．

ログイン後は `role` で教員画面／学生画面に振り分ける．

**授業前にログインを済ませてもらう案内をここに置く**．QRを読んでから未ログインだと，ログインしている間に5秒の有効期限が切れて読み直しになる．「授業開始前にログインしておいてください」の一文を入れておきたい．

## S2. 学生ホーム

```
┌────────────────────────────┐
│  出席管理        [ログアウト]│
├────────────────────────────┤
│                            │
│  こんにちは，○○さん       │
│                            │
│  ┌──────────────────────┐  │
│  │                      │  │
│  │   📷 QRを読み取る    │  │
│  │                      │  │
│  └──────────────────────┘  │
│                            │
│  ┌──────────────────────┐  │
│  │   自分の出席履歴     │  │
│  └──────────────────────┘  │
│                            │
└────────────────────────────┘
```

「QRを読み取る」はブラウザのカメラを起動して読む（`html5-qrcode` など）．端末標準のカメラアプリで読んでも同じ `/scan` に着地する．

自分の履歴以外への導線は画面上に作らない．他人の記録を見る画面はそもそも存在しない．

## S3. 読み取り結果

QRから `/scan?s=12&t=a3f19c...` に来て，`POST /attendances` の結果を出す．

成功（出席）：

```
┌────────────────────────────┐
│                            │
│           ✓                │
│                            │
│      出席を記録しました    │
│                            │
│   情報セキュリティ         │
│   2026/07/27 10:02         │
│   区分：出席               │
│                            │
│  ┌──────────────────────┐  │
│  │       ホームへ       │  │
│  └──────────────────────┘  │
└────────────────────────────┘
```

遅刻のときは「区分：遅刻（開始から8分後の登録）」のように，なぜ遅刻になったかも出す．

2回目以降（在室確認）のときは「2回目の確認が完了しました／区分：出席（変更なし）」．

失敗時の出し分け：

| 状況 | 表示 | 次にすること |
|---|---|---|
| 学外からのアクセス | 学内ネットワークに接続してください | Wi-Fi設定を確認 |
| トークン期限切れ | QRの有効期限が切れました | もう一度読む |
| 無効なQR | 無効なQRです | 教員に申し出る |
| 受付時間外 | 受付時間を過ぎています | 教員に申し出る |
| 未履修 | この授業の履修者ではありません | — |
| 既に登録済み | この回の出席は既に登録されています | — |

```
┌────────────────────────────┐
│           ✕                │
│  QRの有効期限が切れました  │
│                            │
│  QRは5秒ごとに更新されます．│
│  もう一度読み取ってください．│
│                            │
│  ┌──────────────────────┐  │
│  │   📷 もう一度読む    │  │
│  └──────────────────────┘  │
└────────────────────────────┘
```

期限切れからの再読み取りは1タップで戻れるようにする．5秒更新なので失敗はある程度出る前提で，やり直しの摩擦を最小にしておきたい．ここが煩雑だと手動修正への依存が増えて，結果的にセキュリティが落ちる（[脅威モデル](threat-model.md)に書いた通り）．

## S6. QR表示（投影用）

```
┌──────────────────────────────────────────────┐
│  情報セキュリティ  第10回                    │
│                                              │
│        ┌────────────────────────┐            │
│        │                        │            │
│        │                        │            │
│        │       ▓▓  ▓▓▓ ▓▓      │            │
│        │       ▓ ▓▓ ▓  ▓ ▓     │            │
│        │       ▓▓▓  ▓▓▓▓▓      │            │
│        │        （QRコード）    │            │
│        │                        │            │
│        │                        │            │
│        └────────────────────────┘            │
│                                              │
│         次の更新まで  ● ● ● ○ ○             │
│                                              │
│  受付中：出席（10:05まで）                   │
│  登録済み：32 / 40 名                        │
│                                              │
│  [2回目のQRを表示] [QRを作り直す] [セッション終了]│
└──────────────────────────────────────────────┘
```

QRは画面の大部分を占める大きさにする．教室の後ろからスマホで読める必要がある．

更新までの残り時間を視覚的に出す（●○のインジケータやプログレスバー）．切り替わる直前に読み始めて失敗するのを減らしたい．

受付中の区分（出席／遅刻）と締切時刻を出して，教員が状況を把握できるようにする．登録済み人数もリアルタイムに更新する．

5秒ごとに `GET /attendance-sessions/{id}/token` をポーリングして再描画する．

### 「2回目のQRを表示」ボタン

`POST /attendance-sessions/{id}/rescan` を呼んで `required_scan_count` を増やす．事前設定ではなく教員がその場で押す方式．

押した後は「3回目のQRを表示」に変わる（回数の上限はなし）．

確認ダイアログは出さない．学生に気付かれる前に素早く押せた方がいい．

### 「QRを作り直す」ボタン

`POST /attendance-sessions/{id}/rotate-token` を呼んで `token_salt` を作り直す．QRが撮影されて出回った疑いがあるときの緊急対応で，出回っている全QRが即座に無効になる．

こちらは確認ダイアログを出す．実行した瞬間に読み取り中だった学生も失敗して，全員が再読み取りになるため．

> 出回ったQRを無効にします．現在読み取り中の学生も一度失敗します．よろしいですか？

履修者全員を出す．未登録者が「行がない」のではなく「区分が空欄」として並ぶようにする．欠席者を見落とさないため．

「1回目のみ」の学生には警告マークを付ける．ただし自動で欠席にはしない．機器トラブルと中抜けを区別できないので，判断は教員に委ねる．

アラートは画面上部にまとめて出し，該当行にもマークを付ける．

手動修正済みの記録は「手動✎」と出して自動判定と区別する．

手動修正のダイアログ：

```
┌────────────────────────────────────┐
│  出席記録の修正                    │
│                                    │
│  対象：S0004 ○○                  │
│  現在：記録なし                    │
│                                    │
│  変更後                            │
│  ( ) 出席   ( ) 遅刻   ( ) 欠席    │
│                                    │
│  理由（必須・監査ログに記録）      │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │
│  ⚠ この操作は「誰が・いつ・何を   │
│    どう変更したか」が記録されます  │
│                                    │
│         [キャンセル]  [修正する]   │
└────────────────────────────────────┘
```

理由の入力は必須．未入力では「修正する」を押せないようにし，サーバー側でも空を拒否する（画面側のチェックだけに頼らない）．

記録される旨を画面に明示する．手動修正は特権操作なので，記録が残ることを操作者に見せること自体が抑止になる．

## 担当Cへの申し送り

フロント実装で踏みやすいところ．レビューではここを見る．

1. **トークンを `localStorage` に保存しない**．QRから受け取ったトークンはその場で送るだけで，保持する必要がない．保存するとXSSで盗まれる経路を作ることになる
2. **`device_id` をJavaScriptから触らない**．HttpOnlyのCookieなのでそもそも読めないが，別途JSで独自の端末IDを作って送る実装にしてはいけない（クライアント側で偽装できるものを判定に使うことになる）
3. **時刻をクライアントで計算して送らない**．「開始から何分後か」の判定はサーバーがやる．画面に出す残り時間は表示専用と割り切る
4. **画面の出し分けは認可ではない**．「学生には修正ボタンを表示しない」はUIの都合であって認可ではない．APIを直接叩かれる前提で，サーバー側の認可が本体
5. **サーバーのエラーメッセージをそのまま画面に出さない**．例外メッセージやスタックトレースを出すと内部構造が漏れる
6. **QRの描画はクライアント側でやる**（`qrcode.js` など）．サーバーから画像を返す必要はなく，トークン文字列だけ受け取って描画すればいい

## 実装の順番（担当C）

1. ログイン画面（S1）… 他の画面の前提になる
2. 学生の読み取り結果画面（S3）… 担当A・Bのコア実装の動作確認に使える
3. 教員のQR表示画面（S6）… ポーリングと再描画
4. 教員の出席状況一覧（S7）… 一覧と手動修正
5. 学生ホーム・履歴（S2・S4）
